## Entities and backend contract
- `sensor.household_away_status` (household away snapshot). Attributes: `contract_version` (must be 1, else unavailable), `mode` none|solo_trip|vacation, state idle|scheduled|activating|active|degraded|ending|restore_required, `traveler`/`home_resident` (stephen|steph|none), `starts_at`, `ends_at`, `revision`, `command_available`, `blockers`, `effects` {wake_light_source, sleepypod_schedule, sleepypod_live_follow}. `available` = entity exists, state not unknown/unavailable, compatible.
- Commands: `script.household_away_command` with `return_response: true`, data `{expected_revision, operation, request_id (uuid), ...}`. Operations here: `schedule` (mode solo_trip, traveler, start_date, start_time, end_date, end_time), `cancel`, `end_now`, `update_end` (end_date, end_time), `resolve_restore` (resolve_action keep_current|restore_saved). Response `status`/`outcome` accepted|no_change => accepted; else rejected with `error_code`/`error`; 10 s timeout => unknown (`unknown_outcome`). One command in flight; revision tracked as max(seen, acknowledged).
- Vacation helpers: `input_boolean.vacation_mode`, `input_boolean.vacation_mode_invalid_dates_pending`, `input_datetime.vacation_start`, `input_datetime.vacation_end`; checklist `input_boolean.vacation_checklist_{turn_off_outdoor_sprinklers, pour_boiling_water_down_the_drain, make_the_bed, unload_and_check_dishwasher, trash_and_recycles_taken_out}` (titles: "Turn off outdoor sprinklers", "Pour boiling water down the drain", "Make the bed", "Unload and Check Dishwasher", "Trash and Recycles taken out").

## Route resolution (`vacation` link from Settings)
`vacationFeaturePath`: Vacation engaged in snapshot (mode vacation, state not idle) OR `vacation_mode` on OR invalid-dates-pending on -> `vacation-mode`; else Solo Trip engaged -> `solo-trip`; else the chooser. Back from all three goes to `settings`.

## 1. Chooser (route `vacation`, title "Vacation")
Link list (same row as Settings): "Vacation" / "Set away dates and prepare the house for vacation." (mdi:airplane) -> `vacation-mode`; "Solo Trip" / "One traveler, one home resident" (mdi:bag-suitcase) -> `solo-trip`; subtitle becomes "Home Assistant Setup · Learn More" when snapshot unavailable or `command_available` false.

## 2. Vacation Mode (route `vacation-mode`, title "Vacation Mode")
If snapshot mode is `solo_trip` (any state): show only the Solo Trip status section (below). Otherwise two responsive sections:
- **Vacation Mode**: description "Enable or disable vacation mode for the house". Inline alert "All pre-vacation tasks must be checked off before Vacation Mode can be enabled." after a blocked enable attempt (cleared when checklist completes or mode enables). Command error alert from the household controller if any. Wide tile "Vacation Mode" (mdi:airplane):
  - enabled = optimistic `vacation_mode` on OR recovering invalid dates OR backend vacation engaged. Subtitle "Pending" while confirming, else On/Off/Unavailable. Disabled when entity unavailable, controller pending, or recovering with an invalid range. Chevron only when off, not pending, checklist complete. Tint switch-active; security color while pending.
  - Tap when on: optimistic off, `input_boolean.turn_off` vacation_mode and invalid_dates_pending, then `turn_off` every checklist item.
  - Tap when off: checklist incomplete -> show the alert; complete -> open **Confirm Vacation** sheet with default range now -> now+1 day.
- **Second section**: when enabled/recovering/backend engaged -> **Vacation Dates**: description "Set the start and end time for your vacation. Vacation mode will automatically be turned off at the set end date and time."; error "Start date and time must be before end date and time. Vacation mode is disabled until the dates are fixed." when start >= end; four pickers Start Date, Start Time, End Date, End Time from the input_datetime states. Each change immediately calls `input_datetime.set_datetime` {date: YYYY-MM-DD, time: HH:MM:SS} on start or end; if recovering and the new range is valid and in the future, also `turn_on` vacation_mode and `turn_off` invalid_dates_pending. Otherwise -> **Pre-Vacation Checklist**: five checkbox rows, tap -> `input_boolean.turn_on|turn_off` explicit, optimistic; unavailable rows disabled.
- **Confirm Vacation sheet** (form size): same date description and four pickers (local draft only), range error, primary button "Confirm Vacation" (hidden while invalid). Confirm -> set_datetime start, set_datetime end, turn_off invalid_dates_pending, turn_on vacation_mode; close; optimistic enabled. Dismiss -> back to off.

## 3. Solo Trip (route `solo-trip`, title "Solo Trip")
Two responsive sections; state machine in `SoloTripPage` (keep it in a testable view model).
- **Solo Trip**: active notice (InfoBox "{Traveler} Away", success tone when fully active or activating/active; description "While {traveler} is away..." or traveler variant from `status.activeDescription*`) when solo trip and state not idle/scheduled; description "Enable or disable Solo Trip mode for the house."; wide toggle tile "Solo Trip" (mdi:bag-suitcase, rgb 91,141,239). Subtitle: On / Off / "Select the user that will be away from home first." / setup subtitle. Disabled when pending, awaiting a confirmation, editor open, state ending or restore_required, unavailable, vacation engaged, or off with no traveler. Tap off->on opens the editor; on->off (states scheduled/activating/active/degraded only) optimistic off (60 s revert), `cancel` when scheduled else `end_now`. Setup error alert: "Vacation Mode is already engaged. Turn it off before scheduling Solo Trip." or "Solo Trip scheduling is unavailable. Complete Household Away setup, then try again."
- **Away From Home**: description "Select the user that will be away from home"; two selection tiles Stephen, Steph (viewer's own shows "You"). Icons account-arrow-right-outline (selected) / home-account (home resident) / account. Subtitles when engaged: Away / Home; when locked and selected: Selected. Selection locked while editor open, scheduling, engaged, or vacation engaged; tap toggles selection. When snapshot is solo trip with `ends_at`: Return Date / Return Time pickers; each valid change sends `update_end`; alerts "Return date/time must be in the future." / "Return must be after departure.". When engaged: `SoloTripStatusSection` (restore_required: title "Solo Trip Needs Attention", buttons "Keep Current Schedule" / "Restore Saved Schedule" -> `resolve_restore`; ending: "Ending Solo Trip"; degraded: "Solo Trip Degraded"; else unconfirmed description).
- **Schedule Solo Trip sheet**: description "Choose when Solo Trip starts and ends for the selected traveler."; Departure Date/Time, Return Date/Time (default now -> now+3 days); alerts for missing traveler, end not after start, availability, command error ("Home Assistant could not apply the Solo Trip change. Try again." / unknown outcome copy); primary "Schedule Solo Trip" -> `schedule`. Sheet stays open (busy) until the snapshot echoes the same traveler and wall-clock start/end, then closes.
