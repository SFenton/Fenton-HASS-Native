# Home: iPhone and iPad

> **What:** native Home implementation notes. **Read when:** changing `HassUI/Features/Home`.

- `HomeScreen` is a `ScrollView` in a `NavigationStack` with a large title. HIG: Navigation bars, Scroll views.
- Status rail: `StatusRail` horizontal scroll, chips 44 pt min height. HIG: Buttons (hit targets).
- Sheets: `HomeSheet` enum → `.sheet(item:)`, detents per [modal-sheet](../../patterns/modal-sheet.md).
- Cameras: `CameraGrid` on `DynamicGridLayout`; tiles play the camera's live stream (web `CameraTile` → `RtcPilotCamera variant="tile"`, fill-cropped) over its `entity_picture` snapshot (tokenized URL, no auth header needed). Direction G: 22 pt corners and only a small name label over the picture (HIG HomeKit: don't cover camera views); VoiceOver still reads "Live" or "Snapshot" as the tile's value. Streams come from `CameraStreamPool` (web `stream-manager.js` + `rtcStreamRetention.ts`): one `CameraLiveModel` per camera serves every tile and the viewer, so the viewer opens on the frames the tile is already showing; once shown, a stream is retained for the session so Home, Security and the viewer never reconnect; a stream that fails every mode drops its retention so the next view starts fresh; every stream stops in the background and retained ones restart on return. Each stream tries WebRTC first through the WebRTC integration's `/api/webrtc/ws` (signed with `auth/sign_path`, go2rtc stream ids `front_door`, `garage_camera`, `upper_deck`, `lower_deck`; same protocol as `SFenton/WebRTC` `www/stream-manager.js`; video and audio receive-only), then core HLS (`camera/stream`) if WebRTC shows no frame within 10 s (HLS gets 25 s: Home Assistant holds the first playlist request 10 to 13 s while a cold stream warms up), then the snapshot with a retry. A hidden frame monitor on the WebRTC track detects the first frame (so a pooled stream goes live with no view attached) and keeps the latest frame for Snapshot. The snapshot cross-fades out only on the first frame, and `FENTON_REDACT_PRIVATE` keeps the blurred snapshot over the video with the player at zero opacity (the WebRTC Metal view otherwise draws above the snapshot and leaks the picture into screenshots). Tiles hit-test only their own rounded frame (`contentShape`) and the snapshot image is clipped and not hit-testable: the fill-scaled Driveway picture (10:3 in a 16:9 cell) overflowed its tile and took taps meant for Front Door (owner bug, 2026-10-13). Observe `AVPlayer`/`AVPlayerItem` with `observe(_:)` KVO; Combine's `publisher(for:).values` delivered only initial values on iOS 27. HIG: Playing video (live content shows its state; no scrubbing controls for a live feed).
- Camera viewer (`Features/Cameras/CameraViewer.swift`, web `CameraModalContent`): the shared stream with Snapshot, Sound and Record under it as circles in the sheet cell colour with their labels below (direction G) (a row; on iPad and unfolded Duo landscape, where `SplitPolicy` allows a split and the sheet is ≥ 640 pt, video leading and the controls stacked trailing, web `media-split`). Snapshot saves the live frame (WebRTC frame monitor or HLS `AVPlayerItemVideoOutput`; the Home Assistant still if nothing plays) to Photos with add-only access (`NSPhotoLibraryAddUsageDescription`), confirms with "Saved", a success haptic and a VoiceOver announcement. Sound is a toggle (label "Sound", value On/Off); cameras open muted and re-mute when the viewer closes or the app backgrounds. Audio plays through `CameraPlayoutDevice`, a playout-only WebRTC audio device on `AVAudioEngine`: WebRTC's built-in device opens the microphone, which would prompt for mic access just to hear a camera. The audio session (`.playback`) is active only while a camera is unmuted, so opening a camera never stops other audio. Record calls the camera's `script.<camera>_manual_recording` (`script.turn_on`) and reads `input_boolean.is_<camera>_recording`; journeys never press it. HIG: Buttons (labels under icons, ≥ 44 pt), Playing audio.
- Chip sheets: Security opens the Security page's `SecuritySystemSheet`; the other five open the [room overview sheet](../../patterns/room-overview-sheet.md) (room cards, then a pushed room detail with live controls for lights).
- Weather: `WeatherSummaryCard` (`Features/Home/Weather`) is the web `WeatherSummary` card: Direction G (mockup n1 home): a thin module with the glyph and the page's one display numeral (Thin, capped at 96 pt at accessibility sizes), the condition and today's "H:61°  L:47°" trailing (the `home.weather.today` element, read "Today Clear H:61°  L:47°"), the first sentence of the day's briefing, then the 24-hour carousel. The condition gradient stays in the sheet. The header is the card's button ("Open seven-day weather forecast. Rain, 72°F"); the hours are separate elements so VoiceOver reaches each one and scrolling never opens the sheet. The sheet is the card's own `.sheet` (full height, inline "Weather" title, Done), not a `HomeSheet`. Forecasts come from one shared `WeatherForecastStore` (HassCore) that restores its disk snapshot before the first frame. Details, departures and tests: [weather pattern](../../patterns/weather.md). HIG: Scroll views, Page controls, Sheets, Charting data, Accessibility.
