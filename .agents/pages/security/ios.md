# Security: iPhone and iPad

> **What:** native Security implementation notes. **Read when:** changing `HassUI/Features/Security`.

- `SecurityScreen` passes the live `HassConnection` (as `HassServiceCalling`) to `SecurityPage`, which the debug gallery (`FENTON_GALLERY=security`) also hosts with fixture state and a recording caller. Journeys press controls only in the gallery; the signed-in journey opens the real tab read-only. HIG: Navigation bars, Scroll views.
- Status rail reuses `StatusRail` with the Security and Contact Sensors chips (`idPrefix: "security"`). Security opens `SecuritySystemSheet`; Contact Sensors opens the shared `ChipSheet(.contacts)`.
- Direction G (mockup n3): the page is the status rail, the alarm card (`AlarmPanel` in `SecuritySystemSheet.swift`), a "Doors" grid of `SecurityDoorTile`s (owner, 2026-10-16: tiles, not rows; `LockTile` and `GarageDoorTile`, contact family), guest presence, cameras, then a "Mach-E" tile. The alarm card shows a badge in the mode's `ColorFamily.security` fill, the mode as a title with "Since …" (`SecurityConfig.sinceText`), and four mode buttons in the order Disarm, Home, Away, Night (`SecurityConfig.modeButtons`). It sits on a module on the page and on the sheet's cell colour in a sheet (`tileSurface`); a triggered alarm reddens the card.
- Door tiles (`SecurityDoorTile.swift`: `LockTile`; `GarageDoorTile` in `SecurityTiles.swift`) are `GlassTile` buttons in a `DynamicGridLayout` (140 pt scaled minimum, equal heights): label the door, value the state ("Front Door, Locked"), hint what a tap does ("Unlocks", "Closes the door"). A tile is dark while locked or closed and fills with the contact family while unlocked, open or moving; a jammed lock and a failed garage command draw the red error face. A garage tile shows "Sending Open…" / "Sending Close…" while a command is on its way, then the door's own Opening or Closing, or "Error". Identifiers stay `security.tile.<entity id>`.
- Safety: arming sends at once and Disarm always confirms with an alert ("Disarm the Security System?"); garage doors open on tap with no confirmation (spec), and locks send explicit `lock.lock` / `lock.unlock`.
- Garage doors run `HassCore/Security/GarageDoorController` (timers on `RevertScheduler`, unit-tested with a manual clock). `SecurityScreen.canSend` maps disconnected / waiting / rejected to "cannot send", which fails an active request like the web's `connectionCannotSend`. Feedback is announced with `AccessibilityNotification.Announcement`.
- Shared with Rooms: garage room cards draw `GarageDoorTile` (`RoomCardView.garageTile` keeps the card title), and the Quick Links Security System detail reuses `SecurityControls`, the body of the Security System sheet.
- The Security chip opens the same card in a sheet; the alert keeps Cancel on every device (unlike an action-sheet popover). HIG: Alerts.
- `FENTON_REDACT_PRIVATE=1` hides the alarm mode (card header and selection) in shared screenshots.
- Gallery flags: `FENTON_GALLERY_FAIL=1` fails every call (garage error state), `FENTON_GALLERY_CLEAN=1` hides the last-call line, `FENTON_GALLERY_SCENARIO=unavailable|triggered` loads those fixtures.
