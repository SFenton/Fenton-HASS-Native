Proposal · 2026-10-23

Grid minimums follow text size

Five tile grids use a fixed minimum width while their siblings scale it, so at accessibility sizes tiles keep their width and clip the enlarged words.

Cause

Home cameras, Chores quick links, Food hub, Solo Trip and guest presence pass a plain number as minCellWidth (160, 150, 150, 140, 110). Rooms (RoomScreen, 140), household settings and Sprinklers already wrap theirs in @ScaledMetric(relativeTo:). At AX5 the text is about 2.7 times its default size inside tiles that stay the same width, so two 181 pt tiles clip "Unassigned" and "upcoming" (Chores, Solo Trip) and guest tiles stay three across at ~115 pt (Security). Findings: dynamic-grid-layout, chores, chore-quick-links, food-hub, solo-trip, security, guest-presence-section.

The pattern doc (dynamic-grid.md) states the column rule but not that minimums scale. That makes this a shared-pattern change, so it comes to you.

Options

  • A. Scale every grid minimum with @ScaledMetric(relativeTo: .subheadline) (the Rooms recipe), a one-line change per call site. Default size is pixel-identical; at AX sizes the grid steps down to fewer, wider tiles, one column on iPhone and Duo folded.
  • B. Scale in DynamicGridLayout itself (read dynamicTypeSize and multiply). No call site can forget, but sites that already scale (Rooms, Sprinklers) would then double-scale and need to drop their own.
  • C. Status quo plus clip fixes (lineLimit/minimumScaleFactor): rejected, it shrinks the text the user enlarged.

Recommendation

A. It matches how Rooms and Sprinklers already work, leaves the default size untouched, and keeps the layout a dumb container. Add one sentence to dynamic-grid.md ("a minimum is a @ScaledMetric relative to the tile's text style") and one AX5 journey per page asserting no tile is narrower than its longest word. Chores keeps its recorded four-column exception on iPad.
