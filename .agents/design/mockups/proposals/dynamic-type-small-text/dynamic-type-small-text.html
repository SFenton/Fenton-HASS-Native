Proposal · 2026-10-23

Value text off the smallest styles

Where .caption, .caption2 or 9 pt carries the only copy of a state, a name or a number, move it up one step and lift Dynamic Type caps.

Cause

Eighteen findings: text set in .caption (12 pt), .caption2 (11 pt) or a hard 9 pt that carries the only copy of a value or name, several of them also capped with dynamicTypeSize(...xLarge) so they never reach AX sizes. HIG Typography: the default minimum is 11 pt, and information the person needs should not sit at the smallest style.

Options

  • A. Promote one step (caption → footnote, caption2 → caption, hard 9 pt → caption2), lift the xLarge caps where the text is the only place the information appears. Layouts that wrap already will wrap one step sooner.
  • B. Promote to subheadline for value-carrying lines only (chip state line, Default icon label, hour precipitation) and leave decoration (axis ticks, badge numerals) as it is.
  • C. Leave sizes, uncap only. The smallest change, but default-size legibility is unchanged.

Recommendation

A everywhere, plus B for the chip state line and the Live Activity small view where the text is the value. Lift the xLarge cap on the badge and profile count (VoiceOver already speaks them; sighted low-vision readers should not be capped). Tests: an AX5 UX test per surface asserting the label frame is at least the footnote line height; update the affected mockups' reviews from fix to pass when built.
