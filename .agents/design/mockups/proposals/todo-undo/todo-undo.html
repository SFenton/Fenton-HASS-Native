Undo for completed todo items

Completing a grocery or chore removes it with no way back. Three ways to make the tick reversible.

Cause

Ticking an item off (tap or full leading swipe) calls todo.update_item (or script.complete_admin_todo_item on Admin To-Do) and the row leaves at once, because every todo list sets hideCompleted = true (ChoresConfig.swift:56, TodoListSection.swift:22,48-50,74). The "Mark Not Done" row action exists (TodoRowActions.swift:25) but is unreachable: the completed row is never on screen. A stray tap while shopping, or a swipe on a chore assigned to someone else, cannot be reversed from the page. HIG Undo and redo: let people reverse an easy action that removes content. Affects Groceries, Chores, Resident Chores, Unassigned Chores, Admin To-Do and the todo list section component.

Options (Groceries; same list section everywhere)

Accessibility size (AX5) and other devices

VoiceOver (all options): on completion post "Sourdough bread completed. Undo available" and expose Undo as a custom action on the row for B (and for A the bar is a focusable button announced on appear). Reduce Motion: no collapse animation, the row simply disappears after the grace period.

Recommendation

B. It gives the missing confirmation that the tick worked, keeps the user where they are, handles rapid ticking, and needs no overlay. Implementation: TodoListController already tracks pending check-offs; add a short "recently completed" set (5 s) that visibleItems keeps, rendered with the done look and an Undo button calling the existing reopen path (todo.update_item needs_action). Files: TodoListController.swift, TodoListSection.swift, TodoRowActions.swift. Tests: controller unit tests (grace period, undo, rapid ticks), UX and accessibility tests on iPhone, Duo, iPad. Docs: the todo pattern record and the six mockups.
