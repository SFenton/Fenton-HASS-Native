One commit model per form

Two forms save some controls instantly and others on Save or Apply, and Cancel or Back does not say which.

Cause

Two forms mix two commit models and give no hint which control is which (HIG Entering data: be consistent about when changes take effect).

Inventory item editor (InventoryItemEditor.swift:242-302): Quantity and Expiry wait for the ✓ Save, but the Prepared Food toggle calls Home Assistant on change and Delete asks then acts. Cancel (✕) therefore undoes only part of what the form let you edit. Sprinkler program page (SprinklerControllerSheet.swift schedule page, lines 286-354 per the review): Program Enabled and Start Program Now act immediately; days, start times and budget wait for Apply; Back or Close silently drops unapplied edits.

Accessibility size and other devices

Both forms are plain grouped lists, so AX5 only wraps the row labels (already covered by the form-row pattern). On iPad and Duo (unfolded landscape) the sheets keep their form detent; the section headers are the only new text. Footers wrap at AX5 and never truncate.

Recommendation

Inventory A, Sprinkler A. Inventory: the draft already exists for quantity and expiry, and Prepared Food is just another field; Delete keeps its existing confirmation. Sprinkler: turning a program off is something people expect to take effect now, so keep it immediate but say so with two group headers, and add the discard confirmation (this uses the shared confirmation dialog; the Alerts session owns that component, so I will only call it).
