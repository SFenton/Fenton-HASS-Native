# Entity tile

> **What:** the glass tile used for entity controls. **Read when:** showing an entity as a tappable tile.

- `GlassTile(title:subtitle:symbol:tint:isActive:)` draws `.regularMaterial` with a tinted icon when active.
- Semantics follow the web UX contract: chevrons only for navigate/modal; toggles expose `.isToggle` and their on/off value; unavailable entities are dimmed and not tappable.
- Tile size stays stable while values update.
- Disabled (`.disabled`) tiles keep full-contrast text: `GlassTileButtonStyle` never fades the label, and the face mutes only the icon (secondary) and border. A locked tile still carries state ("Away", "Select the user … first"); `.plain` faded it to 2.5:1 and failed the contrast audit (Solo Trip, iPhone, 2026-10-11). VoiceOver still reads it as dimmed.
- Every entity tile draws through `GlassTileFace`; `BrightnessTile` (`HassDesign/BrightnessTile.swift`, web `LightBrightnessCard.tsx`) is the dimmable-light variant. Tap flips power, a horizontal drag sets brightness from the finger's position and commits on release, a vertical drag scrolls. The fill is the light's `rgb_color` (else the light tint) as a 32% wash so labels keep contrast. VoiceOver: activate flips power, adjust steps 10% (the web keyboard steps 5%; 10% keeps VoiceOver swipes practical). Value reads `Off`, `45%` or `Unavailable`. On iOS 18+ the drag is a UIKit pan (`HorizontalPan`) that only begins on a mostly horizontal movement. A SwiftUI `DragGesture`, even attached as a simultaneous gesture, stops a parent `ScrollView` from scrolling when the drag starts on a tile (found 2026-10-11: Custom Lights could not scroll to Reset All Lights). Gesture and optimistic state live in the pure `BrightnessInteraction` value type so tap, drag and adjust are unit-tested; the view only wires gestures and the pending timeout to it.
- `BrightnessTile(onOpen:)` makes a tap open the light's details instead of flipping power (web `tapAction: 'more-info'`, Custom Lights): the tile shows a chevron, VoiceOver's activate opens details and a "Turn On"/"Turn Off" custom action flips power; drag and adjust still set brightness.
- Light power is always an explicit `turn_on` / `turn_off` from the shown state via `LightControl` (`HassCore/Lights`), never `toggle`: Presence Based Lighting's Presence Lock reverts toggles in empty rooms and only honors a bare `turn_on` from an app user. Brightness 0 sends `turn_off`.
- `GlassStateTile` (feature-local in `HassUI/Features/Settings/Household`, until the Room pages lane adds the shared read-only tile) draws the same face with no action, for values with no action (web `EntityActionCard` without an action, e.g. Mach-E). VoiceOver reads the title and the shown state.
- Put a tappable tile's accessibility label, value and traits on its `Button` directly, never behind `.accessibilityElement(children: .ignore)`: that wrapper leaves the Button exposed beside a second element, so an identifier set by the caller, the value and the disabled state land on the non-button one and `app.buttons[id]` finds nothing (found 2026-10-11 on the household Settings tiles). `SelectableOptionRow` follows the same rule.
